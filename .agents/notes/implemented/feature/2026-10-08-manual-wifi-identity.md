# Agent Note: 手动填写 WiFi 身份

Status: implemented

## Problem

用户现在要求自行添加 SSID、BSSID 和 MAC。原界面只提供扫描与备用选择，无法录入自定义身份；PRODUCT.md 与 DESIGN.md 中此前移除手动入口的约束已被此次明确请求取代。已有发布流程笔记属于发布工具领域，与本次功能决定无重叠。

## Decision

WiFi 页保留扫描主操作并增加“手动添加”次要操作，Material 表单仅要求 SSID、BSSID 和设备 MAC。按钮明确标为“保存并使用”，持久保存后统一切换当前身份和受控应用规则。保存失败保留输入；字段校验复用 ProfileValidator，手动保存复用 WifiSelections.saveAndUse 与 ConfigStore 原子文件。

SSID 保留用户输入的首尾空格，因为它们可以属于无线网络名称；BSSID 和 MAC 去除首尾空白并转为小写。相同 SSID/BSSID 更新已有备用项及设备 MAC，保留原 ID、创建时间、使用历史和已采集的频率/信号强度。新身份使用现有模型默认频率及信号强度。手动添加不调用扫描、定位权限请求或设备 MAC/Root 采集。

## Alternatives considered

将手动输入送入扫描选择处理函数可以减少 ViewModel 接口，但该路径会采集设备 MAC 并覆盖用户填写的 MAC，且要求扫描或 Root 条件。直接编辑存储快照可以立即写入，但绕过字段校验、规则切换和原子持久化。因此增加手动入口并复用数据层保存语义。

## Consequences

用户可离线输入身份并后续从备用列表复用；原配置格式和发布签名保持兼容。手动添加同时选用该身份，表单通过文案和确认按钮明确这一影响。当前请求不增加独立编辑页；重新输入相同 SSID/BSSID 可以更新其 MAC。仅提供三个身份字段，不增加频率或信号强度表单。

数据层测试覆盖持久化回读、大小写/空白归一化、已有项更新、规则同步及无效输入拒绝。原生表单仪器测试需要真实 Android 运行时；当前无已连接设备，不能把编译通过作为键盘、窄屏或真实框架视觉验收。

手动保存状态、错误与成功计数由 ViewModel 的 StateFlow 持有，界面按生命周期收集；不把已销毁组合的回调留在保存协程中。屏幕重建时保留输入及起始成功计数，保存完成后仍能关闭表单并切换到备用页。表单明确处理 safe drawing 和 IME insets，正文受限高度可滚动；键盘和大字号仍需设备验收。
